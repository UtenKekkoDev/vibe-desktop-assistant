# Vibe Desktop Assistant

Vibe Desktop Assistant 是 Vibe Voice Lite 的独立派生程序。它直接沿用原版的 Rust 原生悬浮条、录音、SenseVoice / Qwen 转写、托盘、设置界面、结果卡片与三种输入模式。在同一套模式菜单中增加“桌面助手”。

## 本机运行

在构建好的 Windows 程序包中，双击 **vibe-desktop-assistant.exe**，或双击 **start-voice.cmd**。首次设置里选择本地模型或在线识别，保存后通过托盘切换模式。按住助手的录音键说话，松开后处理。桌面助手模式借助原有识别管线获取转写，再调用本地桌面后端；普通听写、开发指令和需求问答继续使用原有处理路径。

原版默认使用右 Ctrl，助手副本默认使用 F9。两个程序的进程、设置目录和单实例标识各自独立。桌面操作以按下录音键时的目标为准。第一次可以说“打开计算器”；输入和发送的适配范围见下文。

从源码构建时，在 `native/` 目录运行 `cargo build --release --locked --bin vibe-desktop-assistant`，然后运行 `.\scripts\package.ps1`。解压生成的程序包后安装下文的桌面依赖，并在设置中选择语音识别模型。桌面助手模式使用 DeepSeek，需求问答也可读取同一 `DEEPSEEK_API_KEY`。语音播报支持 V5 Turbo 和 Qwen3-TTS，模型和本机配置需单独准备。源码中的配置说明位于 `native/docs/TTS.md`，程序包中位于 `docs/TTS.md`。

## 用语音操作当前软件

切到目标窗口，在桌面助手模式说“列出当前窗口的控件”，可以看到 Windows 辅助功能接口提供的具名按钮、输入框和选项卡等。再说“把焦点移到刷新按钮”或“点击刷新按钮”。控件重名、窗口切换或无法核对焦点时，悬浮条会说明情况。按钮调用回执表示软件接受了调用，业务结果需要另行核对。

## 向当前 Codex 或 ChatGPT 对话提问

在当前 Codex 对话（展开侧栏）或 ChatGPT 官方网页中，说“帮我问一下，这段代码为什么报错？”会尝试提交到当前对话。说“先写个提示词，别发：检查这段代码”只写草稿。自动提交需要唯一可调用的发送按钮，助手通过对话中新出现的同文用户消息核对结果。如果没有核对到回执，请先看聊天记录。指定其他项目或聊天时需先切到目标。

## 在 Steam 客户端搜索

在第四种“桌面助手”模式按住录音键，说“在 Steam 商店搜星露谷物语”，松开后助手会切到 Steam，定位商店搜索框、填写关键词并提交。悬浮条在提交后显示“已提交搜索”，核对到匹配的商店结果页后显示游戏名。设置中的“本次运行耗时”可以查看从松键到首次窗口切换或搜索框点击回执的时间。

此功能需要本机安装 Steam。当前项目已准备了微软 UFO 的本地窗口工具。新环境可在此目录运行 `.\setup-ufo.ps1`，需要 Git 和 uv。中文和英文商店的搜索框名称已配置，本机验收使用中文版客户端。

## 可选的免手实验入口

原生桌面助手在「设置 → 输入模式 → 桌面助手」下提供「语音待机」。开启并关闭设置后，悬浮条显示绿色空心圆。单独说“小助手”（可自定义），听到双音提示或看到“已唤醒 · 请说指令”后开口。停顿约 0.9 秒自动提交，每条指令结束后回到待机。七秒内没有说话会取消本次录音。待机使用本地 SenseVoice，指令沿用现有识别与执行设置。按键录音仍然可用。命令行语音实验可用 `node voice.mjs --help` 查看参数。

## 开发与诊断：文字会话

配置 `DEEPSEEK_API_KEY`，按下文安装桌面依赖，然后运行：

```powershell
node assistant.mjs --target '目标窗口的完整标题'
```

逐行输入“在当前输入框写下：周五交付”“把周五改成周四”“先别发”“读一下草稿”。每句话输入后按回车。替换片段在草稿中必须唯一。用 `:target 完整标题` 重新选择窗口，`:status` 查询状态。输入“停一下”或 `:stop` 可以取消等待中的操作。已经发起的桌面动作仍会核对结果。`:quit` 结束会话。

发送依赖可核验的对话身份。微信回车后输入框已空、Codex 或 ChatGPT 中出现新消息时，助手提示“已发送。”。其他软件只确认点击了发送按钮时，会提醒查看窗口。去重与任务状态只在本次进程内有效。

## 用一句话比较本地预算

```powershell
node assistant.mjs --before '上期预算.csv' --after '本期预算.csv'
```

两份 UTF-8 CSV 各含“项目、金额”列；要按分类筛选时两份都添加“分类”列。项目名在每份文件中唯一。说“比较两份预算变化最大的三项”，接着输入“只看人工成本”。结果给出两期金额、有符号差额和文件行号。文件内容由本机读取；发布给模型的是用户输入及任务上下文。此用法只需 Node.js 及 DeepSeek 凭据。

## 桌面依赖与单句入口

本机项目已经装好 Windows-MCP 0.8.9。新环境需要 Windows 10/11、Node.js 24、uv 和环境变量 `DEEPSEEK_API_KEY`。在项目目录运行 `.\setup-mcp.ps1` 安装独立的 Python 3.14 和依赖。已有 uv 程序也可通过 `-Uv` 指定。

```powershell
$python = '.\.runtime\venv\Scripts\python.exe'
& $python -X utf8 desktop.py '帮我打开计算器'
& $python -X utf8 desktop.py '我晚十分钟到' --target '完整窗口标题'
& $python -X utf8 desktop.py '把这段发出去' --target '完整窗口标题'
& $python -X utf8 desktop.py '在当前对话输入「明天见」并立即发送' --target '完整窗口标题'
```

把示例标题换成实际窗口标题。助手优先按完整标题匹配，省略时使用启动命令时的前台窗口。从终端使用时建议指定目标。多个可写输入框中若已有焦点就选择它，也可以用 `--field` 指定辅助功能名称或 AutomationId。可用 `--send-button` 指定按钮。

## 实现与适配范围

- 应用控制通过本地标准输入输出连接 Windows-MCP，按应用名调用 App 工具。已存在同标题窗口时切换到该窗口。
- 填写和发送复用 Windows-MCP 的 UI Automation 库，绑定到具体控件。填写会在原有正文末尾追加内容并回读核对。发送会再次核对窗口及草稿，再调用可访问的发送按钮。在当前输入框要求填写并发送时，会追加到原文后一起发送。
- 桌面入口向 DeepSeek 提交用户指令、已绑定的窗口标题和是否有草稿，草稿正文在本机核对。操作依赖应用暴露可写的 Edit 控件和可调用的 Button。已实测本地 Windows Forms 测试窗体。微信、Codex 和 ChatGPT 各自核对当前会话。
- 两个独立项目分别构建和运行。桌面助手没有占用 Vibe Voice Lite 的快捷键。
